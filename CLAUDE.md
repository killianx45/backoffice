## Project Overview

CMS backoffice application built with Symfony 7.3 for managing users (with different roles), articles, images, and CSV files (for displaying graphs in articles). The frontend will be built with React and consume a Symfony API.

**Stack:**

- **Backend:** Symfony 7.3 (PHP 8.2+)
- **Database:** SQL
- **Frontend Build:** Webpack Encore with Stimulus/Turbo
- **Styling:** Tailwind CSS 4.x + DaisyUI
- **Package Manager:** pnpm for Node dependencies, Composer for PHP

## Development Commands

### Environment Setup

```bash
# Install PHP dependencies
composer install

# Install Node dependencies (using pnpm)
pnpm install

# Start Docker containers (PostgreSQL)
docker compose up -d

# Create database
php bin/console doctrine:database:create

# Run migrations
php bin/console doctrine:migrations:migrate
```

### Development Workflow

```bash
# Start Symfony development server
symfony server:start
# Or with PHP built-in server:
php -S localhost:8000 -t public/

# Watch and rebuild assets automatically
pnpm run watch

# Build assets for development
pnpm run dev

# Build assets for production
pnpm run build

# Run Webpack dev server with hot reload
pnpm run dev-server
```

### Database Management

```bash
# Create a new migration
php bin/console make:migration

# Execute migrations
php bin/console doctrine:migrations:migrate

# Revert last migration
php bin/console doctrine:migrations:migrate prev

# Load fixtures (if configured)
php bin/console doctrine:fixtures:load
```

### Code Generation

```bash
# Create a new entity
php bin/console make:entity

# Create a new controller
php bin/console make:controller

# Create a new form
php bin/console make:form

# Create CRUD operations
php bin/console make:crud
```

### Testing

```bash
# Run all tests
vendor/bin/phpunit

# Run specific test file
vendor/bin/phpunit tests/Path/To/TestFile.php

# Run tests with coverage
vendor/bin/phpunit --coverage-html coverage/
```

### Cache & Debug

```bash
# Clear cache
php bin/console cache:clear

# Debug routes
php bin/console debug:router

# Debug services
php bin/console debug:container

# Debug environment variables
php bin/console debug:dotenv
```

## Architecture

### Directory Structure

- `src/Controller/` - HTTP controllers for backoffice and API endpoints
- `src/Entity/` - Doctrine ORM entities (User, Article, Image, CSV data models)
- `src/Repository/` - Database repositories for custom queries
- `config/packages/` - Bundle-specific configuration
- `assets/` - Frontend JavaScript/CSS (Stimulus controllers, Tailwind)
- `templates/` - Twig templates for backoffice UI
- `migrations/` - Database migration files
- `public/build/` - Compiled assets (generated by Webpack Encore)

### Frontend Architecture

- **Entry Point:** `assets/app.js` imports Bootstrap.js and app.css
- **CSS Framework:** Tailwind CSS 4.x with DaisyUI components
- **JavaScript:** Stimulus for controllers, Turbo for SPA-like navigation
- **Build Tool:** Webpack Encore with PostCSS loader for Tailwind

### Planned API Structure

API endpoints will be created in Symfony to serve the React frontend, providing:

- User management (with role-based access)
- Article CRUD operations
- Image management
- CSV data for charts/graphs

### Database

- **DBMS:** SQL(running in Docker)
- **ORM:** Doctrine
- **Connection:** Configured in `.env` via `DATABASE_URL`
- **Docker Service:** Defined in `compose.yaml`, accessible at localhost:5432

## Key Configuration Files

- **webpack.config.js** - Webpack Encore configuration, defines entry points and build options
- **composer.json** - PHP dependencies and autoloading (PSR-4: `App\` → `src/`)
- **package.json** - Node.js dependencies and build scripts
- **.env** - Environment variables (database, mailer, messenger)
- **config/services.yaml** - Service container configuration with autowiring enabled
- **config/packages/doctrine.yaml** - Doctrine ORM configuration
- **config/packages/security.yaml** - Authentication and authorization configuration

## Important Notes

- Use `pnpm` for all Node.js package management (not npm or yarn)
- Database runs in Docker; use `docker compose up -d` before running migrations
- Assets must be built before they appear in the browser; use `pnpm run watch` during development
- Symfony uses autowiring by default; services in `src/` are auto-registered
- Entity changes require creating and running migrations via `make:migration`
- The project uses Symfony UX Stimulus Bridge; controllers are registered in `assets/controllers.json`

## Design Guidelines

**Visual Style:** The backoffice should follow a clean, minimalist design inspired by modern tools like Vercel, shadcn/ui, and melvynx.com.

**Design Principles:**
- **Minimalist & Clean:** Prioritize whitespace, simple layouts, and clear hierarchy
- **Subtle Colors:** Use neutral grays as the primary palette with minimal accent colors
- **Avoid Extravagance:** No bright, saturated colors or overly decorative elements
- **Professional Aesthetic:** Modern, refined, and distraction-free interface
- **Consistency:** Maintain visual coherence across all pages and components

**Color Usage:**
- Primary palette: Neutral grays (base-100, base-200, base-300 from DaisyUI)
- Accent colors: Use sparingly and only for important actions or status indicators
- Avoid: Multiple bright colors, rainbow badges, excessive use of primary/secondary/accent variants

**Typography & Spacing:**
- Clear visual hierarchy with appropriate font sizes
- Generous whitespace and padding
- Subtle borders and shadows for depth when needed

**Components:**
- Prefer simple, borderless cards over heavily styled containers
- Use subtle hover states and transitions
- Keep badge usage minimal and contextual
- Icons should be subtle and monochromatic where possible
